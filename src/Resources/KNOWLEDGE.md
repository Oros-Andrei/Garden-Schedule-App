# Garden Schedule App knowledge

## What the app does

Garden Schedule is a plant-care guide built with React 18 and TypeScript, with Electron providing a Windows desktop wrapper and Capacitor providing an Android app shell. The interface groups seven built-in plant profiles into four categories and lets the user add named categories and plants with common and Latin names. A selected plant has five views: setup, care, fertilizer, tricks, and diseases. The app also provides a shared garden calendar for logging watering, fertilizing, potting, repotting, and location events.

## Project layout

- `src/index.tsx` initializes Android Preferences before React reads garden records, migrating existing `garden-*` localStorage keys once and restoring the native values into the synchronous browser-style store. Electron still loads its data file before mounting; browser mode uses localStorage directly.
- `capacitor.config.ts` packages the built React assets from `dist` in the Android app. `npm run android:sync` builds and syncs the web app, `npm run android:open` opens the project in Android Studio, `npm run android:run` builds, syncs, and launches on a connected device or emulator, and `npm run android:apk` creates a debug APK. Android uses Capacitor Preferences (Android SharedPreferences) for garden records and app-private files for compressed photos; Add info, plant screens, and the home list use Android-only touch and safe-area styles; the native Activity hides the Android bottom system navigation bar on launch and whenever it resumes, and a bottom-edge swipe can reveal it temporarily. On narrow Android screens, the Menu stays above the plant categories, and opening a plant hides the list to show its profile alone until Close is tapped. Browser and Electron styling is unchanged. The Android launcher uses the sage seedling-and-calendar icon across adaptive and legacy density resources. Android backup export uses the system share sheet, and import uses the Android file chooser.
- `src/Resources/AndroidDataStore.ts` migrates garden localStorage keys to native Preferences once on Android and mirrors later writes for existing synchronous React data access. Export waits for pending native writes before creating a backup.
- `src/Resources/GardenBackup.ts` validates imported browser/mobile backups and merges records by ID while retaining deletion markers, matching the desktop import behavior.
- `src/App.tsx` renders built-in and custom categories/plants; new custom categories can select one of 30 palette colors in Add info, and the chosen color is saved and used for both the category bar and its tinted background. Older categories without a saved color use their existing palette-position fallback. Built-in and custom plants and categories can be deleted with an in-app confirmation; category warnings use the displayed label, and deleting a category also removes all its plants and care data. Deletion IDs persist through browser storage or the desktop bridge so built-in entries stay hidden across restarts and backups. All categories start collapsed when the app opens; adding a category or plant expands its category. Each category has an Options menu with Add a plant and Delete category. The menu closes on outside clicks and after an action. A Menu above the plant categories contains Add info and Export JSON backup, and closes when a pointer press lands outside it. On Android, its row has 16px of spacing before the first category. The Add info dialog adds categories, option values, and room names, with short descriptions of what each add action creates instead of lists of saved values, and its top-right X button closes it. It also renders the add-plant form, backup actions, and either the shared calendar (reloaded when the plant roster changes) or selected plant details. Android has a fixed full-width short arch-shaped Home/Calendar dock with spaced circular buttons and layered shadows. Calendar hides the plant list and any selected profile; its phone view uses compact day cells with up to six colored event dots arranged three per row and a selected-day action row below the grid. Watered events are blue, fertilized light green, potted brown, repotted black, and location yellow. Plant profile tabs stack emoji above labels on phones, and the close control is smaller with reserved header space; the Options control sits below the close control on Android phones. Returning Home restores a selected profile. Touch highlights are transparent, while keyboard focus uses a garden-green outline. Add info uses the plus icon; export and category actions use shared buttons, export uses the tray-download emoji, and Add Plant keeps the plus icon. Plant cards support adding or replacing photos through centered, high-contrast camera controls; uploads up to 10 MB are resized to at most 1200 × 1200 px and compressed to 300 KB or less. Browser photos are stored in IndexedDB; desktop photos are validated and saved in the garden data file, and photos are included in backups and removed when plants are deleted. On desktop, the home view fits the viewport and keeps scrolling inside the plant sidebar and selected plant detail panel, both with the garden-styled scrollbar; smaller screens retain normal page scrolling. Additions immediately flow into setup and calendar pickers, and the X button closes the dialog after each addition is saved. Built-in and custom plant guidance can be added or edited on the Care, Fertilizer, Tricks, and Diseases tabs; saving one section preserves the plant's other records and updates the tab display.
- `src/Components/PlantDetail.tsx` owns a selected plant's tabs, setup edit state, and care-event state; it persists care-event deletions and clears matching potting or repotting setup dates. Its profile header displays an uploaded plant photo beside the name, falling back to the illustration when no photo exists. The header also places a vertically centered, higher-contrast Options menu with spacing beside the plant name for adding/changing a photo or deleting the plant, with the close control kept separate in the top-right corner. It passes profile guidance save requests to the app-level persistence flow.
- `src/Components/Calendar.tsx` renders month views and event details; Android day taps select the date without opening details; the Events action opens the day-details modal, whose Add record action opens the event form for that selected date. Browser day taps keep their existing selection behavior. The add-event dialog includes a Location event and room dropdown sourced from Add info, and users can delete saved records from day details after an in-app confirmation; it filters cached events against active plant IDs so deleted plants cannot appear in either calendar view or day details. Calculated next-repot reminders are read-only.
- `src/Components/GardenCalendar.tsx` builds the all-plants calendar and persists event additions and deletions to local storage and, when available, the Electron bridge. Deleting a potting or repotting event also clears its matching setup date.
- `src/Components/DatePicker.tsx` and `Dropdown.tsx` are custom date and option pickers. The `Dropdown` supports full-width layout for modal forms and compact icon-only selection. `StyledScrollArea.tsx` replaces native scrollbars with custom arrow buttons and a draggable sage-green thumb on a transparent strip and track for dropdown options, the date-picker year list, settings and calendar dialogs, and the main plant and detail panels; wheel, touch, and keyboard scrolling remain available, and mobile page scrolling remains natural. `Button.tsx` supplies shared actions with optional per-action styling, `TextBox.tsx` displays read-only values, and `TextInput.tsx`, `TextArea.tsx`, and `NumberTextBox.tsx` provide shared editable controls for custom plant forms at a consistent 54 px default height; textareas can be resized for longer notes. `NumberTextBox` uses decimal text entry without spinner controls.
- `src/Tabs/SetupTab.tsx` edits pot, substrate, and room details, displays the next-repot date, and embeds a plant calendar with record deletion. Only configured room names are selectable; “Not set” is shown as the Room placeholder. `CareTab.tsx`, `FertilizerTab.tsx`, `TricksTab.tsx`, and `DiseasesTab.tsx` present guidance and let both built-in and custom plant profiles edit those sections; each tab places its Edit information action at the bottom-right after the guidance. Fertilizer uses a compact pie chart that normalizes the NPK ratio to a 100% distribution and shows each element's share in a legend, alongside the Fertilizer Type and Schedule cards in a responsive row. The Diseases tab sorts displayed entries by Minor, Attention, then Urgent without changing their saved order. `src/Components/CustomPlantInfoEditor.tsx` provides the shared section-specific form, initialized with the selected profile's current values; its fields are all optional, fully blank trick or disease rows are omitted when saved, and each trick's emoji is selected from a compact dropdown before its title. The selector includes emoji from the app catalog and all built-in plant tips while excluding interface-only symbols, and it retains a plant's existing custom emoji. Form actions show Save with a seedling icon before Cancel.
- `src/Resources/Constants.ts` contains plant profiles, category definitions, built-in fertilizer/pot/soil options, tabs, weekdays, and severity styles. Each profile includes its care guidance, fertilizer information, tips, disease records, and SVG icon reference.
- `src/Resources/Types.ts` defines the plant and care-guidance model. `src/Resources/GardenData.ts` defines saved garden records, care events, and the desktop bridge types. `Emoji.ts` and `Icons.tsx` provide emoji and inline SVG icons.
- `electron/main.cjs` creates the desktop window, handles JSON file storage/import, validates care events, custom option additions, and compressed plant photos, persists care-event deletions and deleted catalog IDs, and registers IPC handlers. `electron/preload.cjs` exposes a small, context-isolated `window.gardenDesktop` API.
- `src/index.html`, `webpack.config.js`, `tsconfig.json`, and `package.json` configure the renderer and build/package scripts.

## Main data flow

1. In desktop mode, `src/index.tsx` calls `window.gardenDesktop.load()`. It copies saved custom categories, custom plant identities, built-in profile guidance overrides, custom option additions, deleted default IDs, setup, and care events into local-storage keys so the React UI can use the same browser-oriented access pattern.
2. Setup defaults come from each built-in profile. `loadPlantSetup` in `src/Tabs/SetupTab.tsx` overlays valid saved values, including the selected room, with a legacy `garden-soil-<plantId>` fallback; older records without a room default to `Not set`.
3. Setup edits update React state and local storage, then call the desktop bridge's `saveSetup` when running in Electron. The main process writes data to `GardenData/garden-data.json`.
4. Calendar events are represented by a date, type, and ID, with optional fertilizer method, pot/soil details, or room for a Location event. Events are shown in a per-plant calendar and the shared all-plants calendar. Event deletions persist through local storage and the desktop bridge; deleting a potting or repotting event also clears its matching setup date.
5. Custom category records contain an ID, name, and optional selected hex color. Custom plant records contain an ID, common name, Latin name, category ID, source marker, and optional user-entered details for each profile tab. Built-in profiles remain defined by constants, with only changed Care, Fertilizer, Tricks, and Diseases sections stored as per-ID overrides. Both sources join the same runtime plant list used by the category cards, profile selection, and calendar event picker. Saving tab content updates only that section and preserves setup, photo, and care events. Plant-card photos are attached to plant IDs; browser images live in IndexedDB and desktop images live in validated garden-data records.
6. Add info stores user-added fertilizer names, pot materials, soil types, and room names separately from built-in constants. The effective lists are passed into setup/calendar forms; room options appear in plant setup, while the desktop main process accepts fertilizer events only when their method is built-in or configured.
7. Desktop JSON imports validate the format version and plant records, then merge plants, categories, and custom options by ID/value. Export downloads the desktop JSON data when available, otherwise it assembles a backup from browser local storage, including custom records, built-in profile overrides, and options.

## Persistence details

- Data format version is `1`; the top-level shape includes `{ formatVersion: 1, categories: [...], customOptions: { fertilizers: [...], potMaterials: [...], soils: [...], rooms: [...] }, plants: [...], deletedPlantIds: [...], deletedCategoryIds: [...] }`. Older version 1 files without optional lists load with empty lists.
- Packaged portable builds store data beside the portable executable. Other packaged builds use the executable directory; unpackaged development uses Electron's user-data directory. The data folder creates `photos/` and `icons/` directories for assets; compressed plant photos are currently stored in `garden-data.json`.
- Desktop file writes use a temporary file followed by rename. The main process validates imported data and care-event types/dates before saving and persists event removals with setup-date updates.
- Browser mode persists garden records through `localStorage` and compressed plant photos through IndexedDB. Android mirrors garden records in localStorage for the renderer while persisting them in native Preferences; compressed photos live as app-private files under Capacitor's Data directory, in a dedicated folder that is reused if present and created only when absent, with one-time migration from the earlier IndexedDB photo store. Android backup import/export uses the platform file chooser and share sheet. Desktop mode writes garden data and compressed photos through IPC to the JSON file.
- Custom categories/plants and deleted built-in IDs are stored in browser local storage or in the desktop JSON file. Plant photos are compressed to at most 300 KB and 1200 × 1200 px; browser photos are stored in IndexedDB, while desktop photos are stored in garden-data.json and validated when saved or imported. Plant setup and care events use the same per-plant persistence keys and desktop IPC handlers. Deleting any plant or category removes its saved data and photo; category deletion cascades to all plants in that category. Desktop imports merge deletion IDs so removed built-in entries do not reappear.
- Add info additions are stored in browser local storage or `customOptions` in the desktop JSON file. Category and option additions, including room choices, are included in backups; room choices remain available in plant setup.
- Custom plant care, fertilizer, tricks, and disease content is optional. The tabs show an Add information action until a section is saved, then display its content with an Edit information action; built-in plants always show Edit information with catalog guidance prefilled. Browser mode stores custom content in `garden-custom-plants` and built-in overrides in `garden-built-in-profile-overrides`; desktop mode sends the changed section through `savePlantProfileContent`, whose merge preserves other saved plant fields and source identity. Both are included in JSON backups and imports, while built-in names, Latin names, and categories continue to come from constants.

## Build and run

`package.json` defines `npm start` and `npm run dev` for the webpack development server, `npm run build` for a production renderer bundle, Android APK/sync/open/run scripts, and Electron desktop/package scripts. The Android release build uses `proguard-android-optimize.txt` with the app-specific rules file. The desktop window disables Node integration, enables context isolation, uses a preload bridge, and is sandboxed.
